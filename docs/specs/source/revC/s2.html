5.0 ORGANIZATION AND MODULARIZATION

5.1 Principle of division

V1 divided its code mostly by mechanism: how a thing is done (an HTTP read, a Node request, building the page). V2 divides by purpose: what a thing is for (the catalog, the document, storage). A module is defined by the one kind of data it owns, the modules it may call, and the modules it must never call. A boundary that cannot be checked by a script will be bypassed, as fileLayer and nodeLayer were (P-11); every V2 boundary is therefore checkable (FR-6.1.4).

5.2 Layers of the system

Figure 2 is a layered structure chart. A module may call modules in the bands below it and never above. The kernel calls nothing. Only main.js may touch the browser's window object. The Node service is a separate process, reached only through Storage and Catalog.

5.3 Draw separation, sharpened

The owner's rule "UI owns the definition; Draw owns the implementation" held in one direction in V1: nothing in draw/ or classes/ imports from ui/. It blurred in two ways. First, "draw" mixed geometry with painting: drawState.js creates the canvas and holds global ctx, transform, bounds and final, and four draw files touch the page. Second, the interface paints too: discs, weld marks, handles and the script runner call ctx from ui/. V2 keeps the rule and moves its boundary one step earlier than drawLine, as Figure 3 shows.

5.5 Folder layout
