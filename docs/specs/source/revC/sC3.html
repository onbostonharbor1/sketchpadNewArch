16.0 SETTINGS, AND DECISIONS SINCE REVISION B [C]

16.1 The settings command

The owner, 3 November 2026: values accumulated across the specifications (nail size, merge distance, tolerances, limits) should be set in one place, "our equivalent to a settings command". The full catalogue, about seventy values with their defaults, sources and scope, is docs/SETTINGS.md.

FR-16.1Every setting is declared once, in the settings schema, with the same fields as generator settings (type, default, limits, label, section, help). Declaring it is the only step needed to add one.
FR-16.2A setting has a scope: application (one value), or document (each document carries its own value, copied from the application value when the document is made; changing the application value never alters a saved document).
FR-16.3One Settings command, global in scope (6.13), opens one page built from the schema, by section, each setting with its control, its default, a "Default" button and its help.
FR-16.4No tolerance, size, limit or colour is a bare constant in code; code reads settings by name.
FR-16.5A stored value whose setting no longer exists is kept, ignored and listed as unused.
FR-16.6The limits on runaway generation (stitches, time) are one overall setting for now. A finer control (a limit per generator, or one a generator declares) may follow: a huge parametric today usually means a design problem, but may not later.
