1.0 SCOPE

1.1 Identification

This document specifies Sketchpad Version 2 (hereafter "V2"), a rebuild of the Sketchpad application described in the repository onbostonharbor1/sketchpad. Sketchpad Version 1 ("V1") is the application as it stands on branch claude/batch-1.

1.2 System purpose

Sketchpad serves two purposes of equal standing, as recorded by the owner on 27 October 2026:

  1. Templates. To produce a printable point template for driving nails into wood for string art.
  2. Sketching. To explore designs by working directly with how objects are represented and how they relate to one another. Objects kept because they are interesting to play with (Circular Parabola Multi, Linked Circles) are first-class and shall not be treated as clutter.

[B] Making exploration cheap is a major function, not a side effect (owner, 1 November 2026). The model is the gallery script manyRowsColumns.js: copies of a shape added with a slider, neighbours sharing points, so one drag reshapes several shapes at once. It led the owner to designs he would not otherwise have thought of. His aim is original work rather than formulaic craft, and Sketchpad is his assistant for that. Every requirement in this document is judged partly by one test: how few steps does a "what if" take?

Where a design choice in this document trades one purpose against the other, the trade is stated and left to the owner.

3.0 CURRENT SYSTEM AND PROBLEM STATEMENT

3.1 Description of Version 1

V1 is a browser application in plain JavaScript modules, served by Vite on port 5173, with a local Node service on port 5174 that performs every file write. It has six tabs: Home, Draw, Patterns, Figures, Gallery and Utilities. About 27,000 lines are the owner's own code (excluding gallery/, patterns/ and the vendored TinyMCE). The library holds 14 registered Draw objects and about 185 pattern and gallery scripts.

V1 began as a program that runs a drawing script on a canvas. Since Phase 6 it has grown into a geometry editor: objects on layers, discs on infrastructure lines, welds, layer transforms and saving. Much of the work since has gone into adapting the script runner to that editor. V2 starts from the editor and keeps the script runner as one of its uses.

3.2 What V1 does well, and V2 shall keep

  • One file per drawable object, each small and readable, with a header comment the Notes popup shows.
  • Controls declared beside the settings and built by the app, used about 1,200 times across the library.
  • A single drawing choke point (drawLine), and the rule that draw code is separate from the interface.
  • Permanent object names, stable layer numbers, and stacking order kept separate from numbering.
  • Layer transforms (move and turn without rewriting the shape), and infrastructure as a named account of where discs go.
  • categories.js: a list builder with no knowledge of manifests or tabs. The best-isolated module in V1.
  • Gallery scripts as a playpen, never promoted as-is; a local Node service with its path-safety module.

4.0 CONCEPT OF THE NEW SYSTEM

4.1 The central idea

Underneath every line Sketchpad draws is an ordered array of points, and the lines are a rule for joining entries of that array. V2 is built around that fact. A path is an array of points with a flag saying whether it closes on itself. Every drawing is made in four steps: make one or more paths, shape them, connect them into stitches, and find the named points on them. Parametric curves are simply one kind of maker, so the distinction between parametric and non-parametric drawings disappears below the maker (P-18).

Three things are kept strictly apart:

  1. Kernel: the geometry code. Values in, values out. No canvas, no page, no state.
  2. Generators: one file per drawable object or script, declaring its settings and returning geometry. Generators replace both the Draw registry and the script formats.
  3. Documents: plain JSON describing what was made from generators: layers, the point table, welds, transforms. No code and no derived values.

Drawing, hit-testing, thumbnails, welds and printing all read geometry as data (P-1). Every change to a document is a named command (P-7). The folders are the truth, and indexes are worked out from them (P-10, P-13).
